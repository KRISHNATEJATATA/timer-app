# Minute-cadence persistence with crash recovery; sleep auto-pause; PID lock file

The log is now written (a) at every finalize, (b) at most once per minute while a session runs (the write carries an `open` snapshot: topic, startedAt, own elapsed, savedAt), and (c) at session start. On launch, a non-null `open` snapshot means the previous process died uncleanly; its elapsed is appended as a finalized session (start → savedAt) so no tracked time is silently lost. PC sleep is detected heuristically: a tick-to-tick gap over 2 minutes cannot happen while awake (1s ticker), so the session is finalized at the last pre-gap tick — sleep time never lands in a session, and Resume continues the chain from the pre-sleep display total. Only one instance may run: the app takes `app.lock` (its PID) in the data folder at startup; if the lock exists and that PID is alive (checked via tasklist), the new instance shows a message and exits; a stale lock is replaced.
